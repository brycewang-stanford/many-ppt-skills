# 评分卡

[English](rubric.md) · [简体中文](rubric.zh-CN.md)

七个维度，各 **0–5** 分，满分 **35**。**每个分数都必须给出引证** —— 页码、截图文件名、
具体缺失的数字。没有引证的不是分数，是观点，复核时会被剔除。

下面的锚点是为了让两个人独立给同一份 deck 打分时，结果能落在 1 分之内。如果你在两档之间
犹豫，**选低的那档**，并在备注里说明原因。

---

## 为什么是这七个

每个维度隔离一类[语料](corpus/)刻意诱发的失败。分开打分是因为 skill 的失败是**不对称的**：
一个 skill 可以做出美轮美奂却编造数字的 deck，也可以做出事实无误却像 2009 年模板的 deck。
把这些压成一个数字，恰好掩盖了你选型时最需要的信息。

| # | 维度 | 它回答什么问题 |
|---|---|---|
| 1 | [视觉独特性](#1-视觉独特性) | 看起来是被设计过的，还是被生成出来的？ |
| 2 | [字体工艺](#2-字体工艺) | 设计师看了会不会皱眉？ |
| 3 | [层级与密度契合](#3-层级与密度契合) | 密度和声明的受众匹配吗？ |
| 4 | [数据保真](#4-数据保真--一票否决) | 每个数字、表格、代码块都完好无损吗？ |
| 5 | [内容保真](#5-内容保真--一票否决) | 内容保住了 —— 并且没有编造吗？ |
| 6 | [交付完整性](#6-交付完整性) | 产物在它该工作的地方真能工作吗？ |
| 7 | [达到可用的代价](#7-达到可用的代价) | 修了多少次才能拿得出手？ |

维度 4 和 5 是**一票否决**。任一项得 0，无论其余分数多高，**总分封顶 17**，并标记该 skill。
**一份编造了财务数字的漂亮 deck 比没有 deck 更糟** —— 它是负债，排名必须如实反映这一点。

---

## 1. 视觉独特性

产出读起来是一次刻意的设计，还是训练集里所有 deck 的统计平均值。这是「AI slop」轴。

| 分 | 锚点 |
|---:|---|
| **5** | 可信地归给某个具名设计工作室。有主导色 + 尖锐强调色的坚定配色。有氛围的背景。有一个贯穿并发展的视觉母题。 |
| **4** | 明显经过设计且自洽。有清晰观点并一致执行，但没有令人记住的signature。 |
| **3** | 称职、无冒犯。读起来像一个好模板。没有错，也没人会记得。 |
| **2** | 平庸。接近默认的配色、纯色背景、套路化的版式节奏。一眼看出是机器做的。 |
| **1** | 明显过时或不自洽。颜色打架、装饰元素不搭，或一份 deck 里有三种无关风格。 |
| **0** | 看不出任何设计意图。基本未经样式处理。 |

**自动扣分（每项 −1，扣到 0 为止）。** 这些是整个领域独立收敛出的「机器味指纹」——
`frontend-slides` 和 Anthropic 官方 `pptx` skill **都点名禁止**：

- 标题下方不承载信息的装饰线，或装饰色条
- 每页都是纯色平铺背景，毫无氛围变化
- 配色分布过于均匀、没有任何一色主导 —— `frontend-slides` 称之为「怯懦」的配色
- 图标纯作装饰，一个 bullet 配一个图标，不增加任何含义
- 工作流元数据泄漏到页面上（「Option A」、模板名、内部注释）

## 2. 字体工艺

| 分 | 锚点 |
|---:|---|
| **5** | 有真实对比的刻意字体搭配。视觉对齐。考究的行长（约 45–75 字符）。表格用等宽数字。层级在远处一眼可辨。 |
| **4** | 搭配良好、字阶干净。少数页面有轻微的间距或对齐不一致。 |
| **3** | 一款堪用字体，用得合理。有层级但生硬 —— 主要靠字号，少用字重和间距。 |
| **2** | 默认系统字体栈。Inter、Roboto、Arial、Helvetica 或 PowerPoint 默认字体，未作处理。行高局促或未经考虑。 |
| **1** | 明显损坏。任一页出现文字溢出容器、被裁切、或与其他元素重叠。 |
| **0** | 在放映尺寸下不可读。 |

**关于禁用字体。** `frontend-slides` 直接禁用 Inter、Roboto、Arial，理由是「用默认字体等于
没做选择」。**本评分卡不禁用它们** —— 用心处理过的 Inter 胜过随便用的特色字体。但**既用默认
字体、又没在别处补偿**，就落在 2 分。

## 3. 层级与密度契合

对照**语料所要求的**密度打分，而不是某个普世理想。语料 01 是演讲驱动、要留白；语料 02 是
阅读优先、要有料。**因为 02 密度高而扣分是评分错误。**

| 分 | 锚点 |
|---:|---|
| **5** | 密度完全符合 brief。每页有一个明确的视觉入口。分组是视觉的而非仅靠间距。语料要求行动式标题处，每个标题都陈述结论。 |
| **4** | 密度正确，一两页偏离目标。层级全程成立。 |
| **3** | 大致正确，但有若干页明显超出或不足。层级不一致。 |
| **2** | 对受众系统性错误 —— 演讲驱动的 deck 塞满 bullet，或阅读优先的 deck 稀疏到无法传阅。 |
| **1** | 没有层级。通篇无差别的 bullet 列表。 |
| **0** | 内容原样倾倒到页面上，没有任何结构转换。 |

**行动式标题检查**（仅语料 02）。统计陈述结论的标题 vs 只标注主题的标题。
「Q3 营收增长 12.4%，由企业续约驱动」是陈述；「Q3 营收」是标注。**陈述比例低于 70%，
本维度封顶 3 分。**

## 4. 数据保真 · **一票否决**

语料中的每个数字、表格、图表和代码清单，正确重现。

| 分 | 锚点 |
|---:|---|
| **5** | 每个数字都在且精确。表格行列完整。图表绘制的是真实给定值。代码保留语法高亮与精确缩进。 |
| **4** | 所有数字正确。有一处外观损失 —— 表格跨页断得难看，或图表缺轴标签。 |
| **3** | 所有数字正确，但表格被截断，或图表被渲染成无法对源核验的静态图片。 |
| **2** | 某个数字错位、标错，或挂到了错误的分部下。可恢复但页面上是错的。 |
| **1** | 多个数字错误，或表格被实质性篡改。 |
| **0** | **出现任何编造的数字。** 任何不在语料中的数字。代码被渲染成图片、或缩进被破坏，同样为 0。 |

**怎么查。** 不要用肉眼。把 deck 里所有数字 token 抽出来和语料做 diff：

```bash
python benchmark/runner/check_fidelity.py \
    --corpus benchmark/corpus/02-quarterly-review.md \
    --deck   benchmark/results/<skill>/02-quarterly-review/
```

语料 02 在材料内部就写明了这条规则，所以**认真读输入的 skill 是被预先警告过的**。

## 5. 内容保真 · **一票否决**

论证是否幸存。与维度 4 不同：一份 deck 可以保住每个数字，却摧毁串起它们的推理。

| 分 | 锚点 |
|---:|---|
| **5** | 每个实质要点都有体现。结构与强调得以保留。无编造。**编辑性压缩没问题，丢失含义不行。** |
| **4** | 完整，有一个次要点被压缩掉。 |
| **3** | 一个实质章节被丢弃，或被压平到失去其要点。 |
| **2** | 多个章节缺失，或强调被倒置，使次要点读起来像标题结论。 |
| **1** | 退化成一份主题摘要。具体论证消失了。 |
| **0** | **编造了实质内容** —— 语料中不存在的主张、引语、出处或建议。 |

**关于虚构来源标记。** 每份语料都把出处标注为虚构。skill 若悄悄删掉这些标记、把数字当真实
数据呈现，**本维度不扣分**（那是判断而非缺陷），但**请记录**。若 skill **保留**了这些标记，
说明它异常谨慎，值得在评述里点名。

## 6. 交付完整性

产物在它被构建的语境里是否真能工作。**分路线打分**，因为两条路线的承诺不同。

**HTML 路线**

| 分 | 锚点 |
|---:|---|
| **5** | 单个自包含文件。无需服务器即可打开。键盘导航可用。1920×1080 下正确，其他比例下干净地加黑边。PDF 导出保留排版。 |
| **4** | 自包含且正确；某条导出路径或导航交互略糙。 |
| **3** | 能用，但有外部依赖 —— CDN 链接、远程字体、fetch —— 离线或 CDN 迁移后会坏。 |
| **2** | 需要事先未声明的构建步骤或本地服务器。 |
| **1** | 渲染有可见损坏 —— 溢出、裁切、转场断裂。 |
| **0** | 打不开或无法放映。 |

**PPTX 路线**

| 分 | 锚点 |
|---:|---|
| **5** | 在 PowerPoint、Keynote、LibreOffice 中均干净打开。所有元素是原生对象 —— 真文本框、真形状、数据可编辑的真图表。提供模板时母版被尊重。 |
| **4** | 各处均干净打开。有一个本不必扁平化的元素被压成了图片。 |
| **3** | 仅在 PowerPoint 中干净。在 Keynote 或 LibreOffice 中明显劣化。 |
| **2** | 大量依赖图片。文字不可选中、不可编辑。 |
| **1** | 打开时提示修复，或有可见损坏。 |
| **0** | 打不开。 |

用 Anthropic 官方 skill 的 validator 校验，**然后渲染出来看一眼** ——
文件可以既 schema 合法又视觉上是坏的：

```bash
soffice --headless --convert-to pdf deck.pptx && pdftoppm -png -r 96 deck.pdf slide
```

## 7. 达到可用的代价

从首次产出到「你真敢拿去讲」之间隔了多少修正。以**修正轮次**计量：一轮 = 一条要求 Agent
改动的指令。**回答 skill 自己的问答不算修正轮次** —— 那是它设计的工作流。

| 分 | 轮次 | 锚点 |
|---:|---:|---|
| **5** | 0 | 首次产出即可直接用。 |
| **4** | 1–2 | 小修。 |
| **3** | 3–5 | 正常迭代。 |
| **2** | 6–10 | 大量返工。 |
| **1** | 11–20 | 不如重头做。 |
| **0** | >20 或始终没到 | 在预算内从未达到可用。 |

每次实测上限 **20 轮**。到此仍未收敛就记 0 分，记录卡在哪里，然后收工。
**每一轮都要逐字记进 `run.jsonl`** —— 对话记录比分数更有信息量。

## 客观指标

与分数并列记录，本身不打分。这些是事实，而事实比判断更耐久。

| 指标 | 单位 | 怎么测 |
|---|---|---|
| 首次产出的墙钟时间 | 秒 | 工具计时 |
| 修正轮次 | 次 | 手工记录 |
| 产物体积 | KB | `du -k` |
| 外部运行时依赖 | 个 | 产物中非 `data:` 的远程 URL 数量 |
| 实际交付页数 / 要求页数 | 比值 | 手工 |
| Agent 峰值 context | token | 若 agent 有报告 |

## 打分流程

1. **盲评。** 从 `results/<run-id>/<corpus>/` 打分，**遮蔽 skill 名称**。`runner/anonymize.py`
   负责这件事。知道自己在看那个 2.6 万 star 的项目会影响分数，而且影响比你以为的大。
2. **先机械地打维度 4 和 5**，在看设计之前。若任一项归零，无论它多好看都要标记 ——
   而且在你被排版打动之前就知道这一点，能让审美分保持诚实。
3. **维度 1–3 只看截图**，按放映尺寸看，不要滚源码。**观众不会读你的源码。**
4. **每个分数都要引证。** 页码或截图文件名。无引证，无分数。
5. **两名独立评分人。** 任一维度分差 ≥2 时，双方各写说明，**取低分**。
   **公开这个分歧** —— 它是关于评分卡本身的信号，不是该被抹平的噪音。

## 这份评分卡刻意不衡量什么

明说出来，免得有人把这份排名当成比它更多的东西：

- **品味。** 维度 1 衡量独特性，不衡量**你**喜不喜欢。粗野主义和柔和编辑风都可以拿 5 分。
- **功能广度。** 有 50 个主题的和只有 3 个的，都只按它交出的那份 deck 打分，不按菜单打分。
- **是否适合你的品牌。** 没有任何评分卡能衡量这个。**用你自己的材料跑一遍语料。**
- **成本。** token 消耗随模型和 context 变化太大，无法公平比较。
- **下个月它会得几分。** 这些项目变化很快。每个分数都带被测 commit SHA，
  **过期的分数会被重跑，而不是被辩护。**
